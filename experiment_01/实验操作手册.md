# HarmonyOS 联邦学习投毒与防护实验操作手册

## 1. 实验目标与提交物

本实验在 HarmonyOS 端侧模拟联邦学习的三种条件，并解释攻击与防护的差异：

1. **干净基准**：无恶意客户端、正常聚合，观察模型收敛和测试精度。
2. **投毒无防御**：恶意客户端占 20%，执行更新放大（PPT 收获页提及 5x），使用普通 FedAvg 聚合，观察准确率和损失变化。
3. **投毒加防御**：保持同一数据划分、随机初始化和攻击条件，只将聚合规则改为 Trimmed Mean，观察异常更新是否被滤除。

模型为 784 维输入、10 类输出的线性分类器，共 7,850 个可训练参数。每组运行 10 轮，记录每轮 Accuracy、Loss 和 PPT 界面提供的收益指标。PPT 给出的预期参考是干净/防御结果约 99.5%，防御相对受攻击组约提升 35.5 个百分点；这只是课程材料的预期，不应为对齐数字而改动实测结果。

提交物包括三组完整 `fl_*.csv`、关键 ArkTS 代码说明（`FLModel.ets`、`Defense.ets`）以及三组曲线和隐私隔离/部署边界分析。

## 2. 环境怎么选

### 推荐：Windows 本机

把 **Windows 作为开发和模拟器运行环境**。PPT 指定 DevEco Studio、ArkTS 和 HarmonyOS 本地 phone 模拟器；也要求 BIOS 开启 Intel VT-x 或 AMD-V。建议至少 16 GB 内存、20 GB 可用 SSD 空间。若机器内存有限，模拟器运行时关闭大型应用。

从华为开发者官网获取 DevEco Studio。安装并首次启动后，按 IDE 提示安装 HarmonyOS SDK 及 Node.js/ohpm 工具链。设备管理器中创建 phone 模拟器，工程所需 compatible SDK 标为 6.1.1 (24)，材料同时标注 API 9+。SDK/API 的实际兼容性以课程提供工程的 `build-profile.json5`、`module.json5` 和 IDE 检查结果为准，不要仅凭 PPT 数字手动降级 SDK。

### Ubuntu 虚拟机的定位

本实验不建议把 Ubuntu 虚拟机作为主要运行端。PPT 指定 DevEco Studio 的 HarmonyOS phone 模拟器，但没有给出 Ubuntu 模拟器支持说明。Ubuntu VM 可用于整理报告、查看/绘制 CSV 曲线或阅读代码；若要在 Ubuntu 里开发或运行模拟器，先核实课程工程和对应版本 DevEco/SDK 的官方支持，不要默认它与 Windows 配置等价。最省事的路线是 Windows 主机完成 IDE、模拟器和三组实验，Ubuntu 只做可选的数据分析。

## 3. 安装与准备

1. 确认 Windows 版本、内存和磁盘空间满足课程建议；在 BIOS/UEFI 中确认 CPU 虚拟化已开启。若 Windows 的虚拟化平台、Hyper-V 或其他模拟器占用造成冲突，按 DevEco Studio 当前版本的官方模拟器指引处理，不要同时盲目切换多套虚拟化设置。
2. 安装 DevEco Studio 并启动。通过 IDE SDK Manager/首次配置向导安装工程要求的 HarmonyOS SDK 与工具链。等待索引和组件下载完成。
3. 通过 Device Manager 创建 phone 模拟器，启动到系统桌面。保留足够内存给 IDE 和模拟器。
4. 找到课程实际发放的 ArkTS 工程目录。PPT 中列出模块名，但本次提供的文件只有 PPT，没有工程源码或逐屏界面说明；如果教师另有压缩包/仓库，先解压或克隆到本机路径，再用 DevEco Studio 打开**工程根目录**（包含工程级配置文件的目录），等待同步完成。
5. 若没有工程源码，不能仅凭 PPT 中的模块清单直接运行实验。向教师确认工程包/仓库和启动说明；不要把新建空白 ArkTS 项目误认为实验工程。收到工程后检查是否包含：`model/FLModel.ets`、`model/FederatedExperiment.ets`、`defense/Defense.ets`、`model/ExperimentReport.ets`、`model/SeededRandom.ets`、`pages/Index.ets`。
6. 检查工程配置的 compatible SDK 与本机安装版本一致，等待依赖同步结束。选择已启动的 phone 模拟器作为运行目标，执行 Build/Run。首次构建耗时较长属正常；若失败，先记录完整错误并对照工程要求的 SDK/依赖版本，不要先改业务代码。

**截图提醒 2**：保存 DevEco Studio 版本、SDK/compatible SDK 配置页面，以及 Device Manager 中 phone 模拟器已启动的画面。

## 4. 实验前固定条件

正式采集前，先查看工程界面及 `SeededRandom.ets`、`FederatedExperiment.ets`，确认三组使用相同随机种子（PPT 写明 `20260909`）、相同客户端总数、相同数据划分、相同测试集和初始权重。客户端总数在 PPT 里没有指定，按工程默认值或教师要求使用，并在记录中写明。恶意比例设为 20%；攻击类型选课程工程提供的更新放大/模型更新放大选项，攻击倍率按材料设为 5x（若 UI 或代码定义不同，记录实际值并向教师核实）。每组 10 轮。

测试集应独立于训练数据。开始正式实验前，记录模拟器、工程版本/提交号（如有）、SDK、客户端数、随机种子、恶意比例、攻击倍率、轮数和防御策略。每次运行前确保结果使用不同文件名，避免覆盖 CSV。

**截图提醒 4**：截取实验参数面板，确保客户端数、恶意比例、攻击类型/倍率、轮数、随机种子（若可见）和防御策略可辨认。三组参数界面都留档，尤其证明只有预定变量变化。

## 5. 三组实验操作

每组都从相同初始状态开始。若工程每次运行会推进随机数状态或保留全局权重，按界面/代码的重置功能重新初始化，确认仍使用相同种子和初始权重。不要让第二、三组接续上一组训练后的模型。

### A 组：干净基准

1. 设置恶意客户端比例为 0%（或关闭攻击），关闭投毒。
2. 聚合策略使用 FedAvg/普通加权平均。
3. 启动 10 轮实验，逐轮观察准确率、损失及收益。
4. 完成后点击“保存结果”导出沙箱 CSV；也可用“复制 CSV”，粘贴到文本文件并以 `.csv` 保存。检查文件含 10 轮记录、列名和数值完整。
5. 将文件命名为 `fl_clean_seed20260909.csv`（如果应用生成文件名，则保留原件并复制一份改名归档）。

**截图提醒 5**：至少保存运行开始/进行中、10 轮完成结果、最终曲线或结果表、CSV 导出成功/复制内容，以及 A 组 CSV 文件内容。

### B 组：投毒、无防御

1. 重置实验，恢复同一随机种子、数据划分和初始权重。
2. 恶意客户端比例设为 20%，攻击类型选更新放大，倍率设为 5x（依工程实现确认）。
3. 聚合策略选 FedAvg/无防御。
4. 运行 10 轮并记录每轮准确率、损失和收益。
5. 导出并归档为 `fl_poison_fedavg_seed20260909.csv`。

**截图提醒 6**：保存参数设置、实验进行/完成、结果曲线或表格、CSV 内容；确保截图能看出“20% 恶意 + FedAvg”。

### C 组：投毒、Trimmed Mean 防御

1. 再次完全重置，确认种子、数据划分、初始权重、客户端数、20% 恶意比例、5x 攻击和 10 轮与 B 组一致。
2. 只把防御/聚合策略改为 Trimmed Mean（截断均值）。如界面还有 Krum 选项，本次核心对照先不要选 Krum；Krum 是 PPT 列出的扩展实现，不是三组核心比较之一。
3. 运行 10 轮，观察是否比 B 组恢复准确率、降低损失。
4. 导出并归档为 `fl_poison_trimmed_mean_seed20260909.csv`。

**截图提醒 7**：保存与 B 组同样的参数和结果证据，并确保策略显示 Trimmed Mean。另截取三组最终结果并列对照的画面；若应用不支持并列展示，可在报告中用 CSV 绘图后截图。

## 6. CSV 检查与结果分析

用 Excel、LibreOffice 或 Python 打开三份 CSV。保留原始文件，不要覆盖编辑。确认每份包含 10 轮数据及 Accuracy、Loss、收益等工程实际输出列；将字段含义、单位和准确率是 0–1 还是百分数确认清楚。绘制按轮次变化的 Accuracy 曲线和 Loss 曲线，三组放在相同坐标范围内比较。可再做汇总表：最终准确率、最终损失、最佳准确率、收敛轮次（如可定义）和防御相对攻击组的百分点差。

解释时围绕实测数据回答：干净组收敛如何；投毒组从哪一轮开始偏离、准确率下降/损失上升多少；Trimmed Mean 是否压制极端更新、恢复多少；若未达到 PPT 预期，分析随机性、客户端数、数据异质性、截断比例、攻击实现和模型初始化，不要改写结果以迎合预期。

**截图提醒 8**：保存三份 CSV 的文件名/文件夹、表头与逐轮数据、三组对照曲线和汇总表。图例和坐标轴要清楚，报告截图不要裁掉曲线标签或数据来源。

## 7. 代码与安全边界说明

报告至少解释：

- `FLModel.ets`：784→10 线性模型的前向计算、损失与反向梯度；参数量 784×10+10=7,850。
- `FederatedExperiment.ets`：合成数据生成、本地客户端训练、每轮通信/聚合和评估流程；说明训练样本留在客户端，上传的是参数更新。
- `Defense.ets`：FedAvg 的按样本量加权；Trimmed Mean 对每个参数维度排序并去掉两端极值后求均值（具体裁剪规则以代码为准）；若说明 Krum，阐明其基于更新间距离选择较可信更新。
- `SeededRandom.ets`：固定种子如何保证可复现；指出同种子不等于不同环境下绝对逐位一致，仍要记录版本与参数。
- 隐私边界：本实验用合成特征数据和本地沙箱模拟数据留端，不代表已经验证真实设备分布式软总线、硬件密钥加密或真实多终端部署。不要把模拟器实验描述成真实设备安全认证。

## 8. 常见问题与排查顺序

- **模拟器无法启动/很慢**：先检查 BIOS 虚拟化、可用内存、磁盘空间及 IDE 当前版本对模拟器的要求；重启后再启动模拟器，避免同时运行多个高负载虚拟机。
- **工程无法同步或构建**：确认打开的是工程根目录；确认 SDK/compatible SDK、Node.js/ohpm 依赖及网络访问符合工程说明；保存完整错误信息后处理。
- **模拟器找不到应用/运行按钮不可用**：先确认模拟器已进入系统桌面、IDE 运行目标已选择该设备，随后检查工程模块配置和构建错误。
- **三组结果差异不明显或无法复现**：核对攻击是否真的启用、恶意比例/倍率是否生效、聚合策略是否切换、每组是否重置，以及是否共享初始化、数据和测试集。保留异常结果并在报告解释。
- **CSV 未生成/乱码**：使用应用内“复制 CSV”作为备份，粘贴到 UTF-8 文本文件或表格软件；核对分隔符、列数和轮数，不要只依赖应用文件管理器路径。
